PICO trigger driving a simulated Dex1-1

The analog trigger of the PICO 4 Ultra Enterprise controller drives a Dex1-1 gripper model in MuJoCo in real time. This page explains the signal path, the checks made and the open questions.

Relevance: in the real-gripper handheld option (D01), the controller trigger is the gripper command. The test confirms that the trigger value can reach a PC and drive a gripper model before the hardware is delivered.

1 Controller to headset app

The app reads the trigger as a float between 0 and 1 (Unity CommonUsages.trigger) and puts it into one JSON message together with pose and button data. JSON is plain text with named fields.

Source: XRoboToolkit-Unity-Client, Assets/Scripts/TrackingData.cs. Assets/ is the app's source folder in that public repo. It is not in msc-thesis and not on the lab PC.

2 Headset to lab PC

The app sends one JSON message 90 times per second to TCP port 63901 of the lab PC. TCP acknowledges data and resends lost data. A port is a numbered entry point of a computer, and the ufw firewall of the lab PC must allow it. The headset app needs "Tracking → Controller" and "Data & Control → Send" switched on, otherwise the trigger stays 0.

3 Lab PC: receiver, Python bridge, sender

Three programs run in a chain, shown below. The sender polls the trigger 30 times per second and forwards each value as one UDP message to the Mac. UDP does not resend, so a lost value is replaced by the next one 33 ms later.

4 Mac: MuJoCo model

dex1_1_mujoco.py takes the newest UDP message as the actuator command (0 open, 1 closed) and steps the simulation. It holds the last value if messages stop.

Why a Linux PC sits in the middle

PC Service and SDK exist for Windows and Linux only (no macOS build, per the XRoboToolkit READMEs). The Linux PC terminates the headset stream, and the Mac only runs the model.

Checks and findings

Each card states its basis: measured in the test, read in public source code, or taken from the published paper.

Measured

End-to-end chain works

The fingers followed the right trigger. 425 UDP messages arrived in about 14 s with 0 lost (checked with the sequence numbers).

Measured

Model travel

Pad gap 80.0 / 39.0 / −2.0 mm at trigger 0 / 0.5 / 1 (--check). Each finger travels 0.041 m per URDF 261030. Stiffness and damping are chosen values, not Dex1-1 data.

Source code

Timestamp is headset time at packing

timeStampNs is the headset UTC clock when the JSON is packed (DateTime.UtcNow), not the sensor sample time. The offset to the recording-PC clock is unmeasured (research gap B7, now partly resolved).

Source code

90 Hz source, 30 Hz poll

Adequate for the model. A recorder needs all 90 Hz: the SDK getters return only the newest value, and trigger and timestamp are read in separate calls, so a pair can come from two messages.

Source code

Two mappings in two toolkits

XRoboToolkit: linear 0 to 1. Unitree: 10 − 10t, interpolated over [5, 7] to [0, 5.4] rad, ±0.18 rad per step at 200 Hz. The VR baseline and the handheld need the same mapping (research gap G2).

Source code

Ports confirmed

63901 (headset to PC) and 60061 (gRPC, localhost) match the measurement. UDP 42952 is most likely the sending port of a 5 s discovery broadcast to UDP 29888 (unverified), so its ufw rule is probably unnecessary.

Paper

No trigger latency published

zhao2025, Table II, reports video latency only (82 to 100.5 ms). Trigger-to-gripper latency has to be measured.

Open questions

Open

Trigger resolution and dead zone

Number of distinct values and linearity are undocumented. Method: log a slow 20 s squeeze and count the distinct values.

Open

Squeeze-to-motion latency

Needs a measurement along the whole chain.

Open

Clock offset and drift

Headset clock against recording-PC clock, over a full session (B7).

Open

Link reliability over a session

The run lasted about 14 s. Wi-Fi stalls over 1 to 2 h are unmeasured. Hold-last-value hides a stall in a recording, and the timeout behaviour of the real gripper is undecided.

Open

Real finger stroke

Official URDF about 82 to 83 mm, product page 90 mm. To be measured on the real gripper.
